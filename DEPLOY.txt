배포 절차
=========

1) Supabase 프로젝트 준비
   supabase link --project-ref <PROJECT_REF>
   supabase db push

2) Supabase 시크릿 설정
   supabase secrets set \
     ADMIN_PASSWORD='<강한 비밀번호>' \
     ALLOWED_ORIGIN='https://<project>.pages.dev,http://localhost:5173' \
     IP_HASH_SALT='<임의의 32자 이상 문자열>'

   SUPABASE_URL과 SUPABASE_SERVICE_ROLE_KEY는 런타임이 자동 주입하므로
   직접 설정하지 않는다.

3) Edge Functions 배포
   supabase functions deploy lookup
   supabase functions deploy admin-import

4) Cloudflare Pages 설정
   - 저장소: trustspirit/matching, 브랜치: main
   - 빌드 명령: pnpm install && pnpm --filter web build
   - 출력 디렉터리: apps/web/dist
   - 환경 변수: VITE_API_URL=https://<PROJECT_REF>.supabase.co/functions/v1

5) 배포 후 확인
   - https://<project>.pages.dev/ 접속 → 로그인 화면이 뜬다
   - 잘못된 코드로 401이 오는지 확인
   - REST 엔드포인트가 막혀 있는지 확인:
       curl "https://<PROJECT_REF>.supabase.co/rest/v1/participants?select=*" \
         -H "apikey: <ANON_KEY>"
     → 참가자 데이터가 나오면 안 된다. 나오면 RLS를 즉시 점검한다.

6) 실제 데이터 투입
   - 최종 엑셀을 CSV로 저장 (컬럼 순서는 DEPLOY 문서 상단 참고)
   - /admin 접속 → 비밀번호 + CSV 업로드
   - 다운로드된 참가자_코드.csv를 안전한 곳에 보관
   - 참가자에게 이름과 코드를 전달

주의
----
- 평문 코드는 업로드 응답에서만 얻을 수 있다. 서버에는 해시만 남는다.
- 조를 추가하는 재업로드는 기존 코드를 바꾸지 않는다.
- "전원 코드 재발급"을 켜면 이미 배포한 코드가 전부 무효가 된다.
